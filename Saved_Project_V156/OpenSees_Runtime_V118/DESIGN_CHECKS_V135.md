# V135 design checks: what a PASS means

Launch `RUN_ETABS_TO_OPENSEES.py`, then **ULS / SLS design checks - combinations, drift, sections** in the analysis column. Select the export folder. Refresh evaluates saved outputs and writes a timestamped JSON, CSV tables, Excel workbook and processing log into `OpenSees_Analysis_Results/Design_Checks_V135`. Rebuild the export to copy the new runtime into it. Existing V134 features are retained.

## Linear design
A successful solver, gravity equilibrium, or drift check does not prove section strength. Use signed member-end and interior-station actions from every governing combination. Check axial/biaxial interaction, shear, torsion, stability, reinforcement and capacity-design/detailing requirements under the approved material standard. Required and provided reinforcement must be compared using actual material strengths, cover, longitudinal/transverse reinforcement, anchorage and section geometry. The illustrative M35 fiber presets do not establish capacity of the source M45 building.

NBC 105:2025 3.6.1 combinations include 1.2DL+1.5LL, the conditional S cases, DL+lambda LL +/-E and 0.9DL +/-E. Lambda is 0.6 storage / 0.3 other. The nonparallel option expands both leading axes and all signs of 100%+30% effects (3.6.2). The module lists centered and both accidental-eccentricity cases separately. Review vertical earthquake applicability under 3.6.3/4.3 and other applicable wind, earth, liquid and snow requirements. These open items are not silently marked satisfied. ULS/SLS refer to the appropriate seismic action and stiffness context; the registry does not assert that factored gravity is an ordinary sustained service-deflection load case.

`Action_Basis_V135.csv` accepts signed FIRST-ORDER linear increments, in common local axes at matching stations, with selected model SHA256. DL and LL are unfactored increments without preloaded gravity. Use state-specific EX/EY_E0/EPLUS/EMINUS cases. Total responses with gravity, nonlinear actions, second-order results and positive CQC component envelopes are rejected. Second-order combinations must be solved explicitly, not reconstructed through linear superposition. Bidirectional history orientations are already simultaneous excitations; do not apply an additional orthogonal 30% rule to them blindly.

`Section_Criteria_V135.csv` evaluates supplied reviewed demand/limit criteria. Record source, exact clause, existing result evidence path, matching model SHA256, units, case, member, and concurrent action/station/time identifier. An axial/biaxial interaction criterion needs an approved interaction calculation, not separate maxima of N/My/Mz. Individual supplied criteria can PASS/FAIL; whole-section inventory remains NOT EVALUATED until a complete design engine/coverage attestation is implemented. This release does NOT calculate new RC reinforcement demand or a code interaction surface.

## Serviceability and displacement
NBC 105:2025 5.5.3 drift limits: ULS 0.025, SLS 0.006. Existing design-drift CSV and MRSM JSON are compared with these limits for both states. Each row preserves its result path; saved legacy rows do not prove their model fingerprint or complete suite coverage. Verify their provenance. Force-only MRSM base-shear scaling is not applied to displacement. Do not substitute roof displacement/height for interstorey drift.

`Deflection_Criteria_V135.csv` supports reviewed member vertical deflection, incremental deflection after partitions/finishes, roof displacement or other project limits using demand and limit in the SAME unit. Enter the actual adopted material-code/project clause and analysis evidence. No arbitrary L/250, L/350 or H/500 default is imposed. Long-term effects, creep/shrinkage, support-chord movement and construction sequence are not inferred from an instantaneous elastic gravity plot. This module checks supplied values; it does not create these missing analyses.

## Nonlinear performance
Use `Nonlinear_Performance_V135.csv`: performance objective, force/deformation control type, suite statistic, ULS/SLS hazard context, case/member, response demand, calibrated acceptance limit, unit, concurrent record/time or envelope-method ID, model SHA256, reviewed=true, source/clause and existing result evidence path. The evaluator compares absolute demand / positive limit. Force-controlled brittle actions still need strength checks; ductile response requires deformation/strain/rotation acceptance and capacity-design safeguards. Global drift alone cannot establish local acceptance. No generic IO/LS/CP values are invented or assigned to NBC. Project-calibrated wall, frame and device behavior remains required. Do not divide nonlinear responses by a ductility factor as if they were elastic design actions. The existing readiness gate is retained.

Nonlinear histories currently do not export a complete set of member hinge/strain/rotation histories. These acceptance checks require recorded/calibrated inputs; the templates do not manufacture them. Likewise, no nonlinear or second-order load combination is solved by this report collector.

## Sources
Governing seismic reference: NBC 105:2025, 2.4 capacity design, 3.6 combinations, 3.4 stiffness, 5.5 displacements, 7 MRSM, 8 elastic history, 9 nonlinear methods:
https://ebps.kathmandu.gov.np/UploadFiles/NBC_105_2025_Sesmic_Design.pdf
Material resistance, reinforcement and component acceptance require the explicitly adopted material code and experimental calibration. The module stores the exact source/clause per supplied criterion rather than claiming NBC alone supplies every material capacity or deformation limit.

## Validation and limits of this release
The new report was executed against the workspace model and saved SLS/ULS MRSM results: 300 drift rows, 2037 source-object inventory rows, 56 parallel combination entries. No reviewed member criteria were supplied, so there is no section-design PASS and no nonlinear-performance PASS. New report execution does not rerun the building analysis. V134 numerical analyses and their validation files are historical evidence, not a fresh V135 nonlinear/strength validation. Live D: model files were not changed.
